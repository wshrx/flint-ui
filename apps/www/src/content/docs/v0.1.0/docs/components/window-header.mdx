## Usage

Under the native titlebar:

```tsx
import { WindowHeader } from "@/components/ui/window-header"
import { Button } from "@/components/ui/button"

<WindowHeader
  title="Alpenglow"
  trailing={<Button size="sm" variant="ghost">Settings</Button>}
/>
```

On macOS with a transparent titlebar, leave room for the traffic lights:

```tsx
render(<App />, { title: "Alpenglow", titlebarTransparent: true })

<WindowHeader title="Alpenglow" leadingInset={78} />
```

## Keyboard and accessibility

The header is layout, not a control: no role, no tab stop. The title is text; the buttons you pass in
`leading` and `trailing` keep their own names and key handling. Do not make the whole strip
clickable: a window header that swallows clicks is a trap.

## Platform notes

GPUIX 0.11 exposes window actions (`minimizeWindow`, `zoomWindow`, `toggleFullscreen`) but not window
dragging or closing. A custom titlebar with drag and a close button is not possible, and on Wayland
client-side decorations belong to the compositor. This component is the part that is portable: a
safe-area aware strip with slots.

- macOS: pair with `titlebarTransparent: true` and `leadingInset={78}`; native traffic lights keep
  close, minimize and zoom.
- Windows: the native titlebar stays; this is the first row of the app.
- Wayland/X11: the compositor draws the decorations; `appId` groups the window, and this header
  starts below the native chrome.

## When not to use it

For a page heading inside a tab or a card, use `Text` and `Separator`. The header is for the window
frame, not for every section.
