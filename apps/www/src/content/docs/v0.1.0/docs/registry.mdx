`registry/registry.json` is the contract between the source tree, the CLI and the docs. The CLI
validates it on every `init`, `add`, `list` and `diff`: structure, unique names, non-empty file
paths and resolvable `registryDependencies`. It does not check that the named files exist; `bun run
registry:check` does that. The field names follow shadcn's registry format, but the schema is
flint's own and the components target GPUIX, so shadcn cannot install them.

## The file

```json
{
  "$schema": "https://wshrx.github.io/flint-ui/schema/registry.json",
  "name": "flint",
  "items": [
    {
      "name": "dialog",
      "type": "registry:ui",
      "description": "Portal, backdrop and surface with a close control.",
      "registryDependencies": ["theme", "utils", "theme-provider", "icon", "text"],
      "files": [{ "path": "components/ui/dialog.tsx", "type": "registry:ui" }]
    }
  ]
}
```

| Field | Required | Notes |
| --- | --- | --- |
| `name` | yes | what you pass to `add` |
| `type` | yes | `registry:ui`, `registry:lib` or `registry:file` |
| `description` | no | shown by `list` |
| `registryDependencies` | no | names resolved and copied first |
| `files[].path` | yes | relative to the registry root, and the path written into the project |

Paths are preserved on purpose. `components/ui/button.tsx` becomes `<root>/components/ui/button.tsx`,
and its `@/lib/flint/...` imports keep working because the project maps `@/*` to its source root.

## Adding a component

1. Write the component in `registry/components/ui/name.tsx`. Import shared code through `@/lib/flint/...`
   so the file works unchanged after it is copied.
2. Add a page under `apps/www/src/content/docs/docs/components/name.mdx` with usage, props,
   keyboard notes and the source rendered from the file.
3. Add the item to `registry.json`, listing every file and every dependency.
4. Run the checks:

```bash
bun run typecheck
bun run contrast
bun run registry:check
bun run build
```

`registry:check` verifies that every file named in the JSON exists, that every dependency resolves,
and that no item depends on itself.

## Shared primitives

Shared code lives in `registry/lib/flint/` and uses `type: "registry:lib"`. Give it an item, then
list that item in the `registryDependencies` of every component that imports it:

```json
{
  "name": "utils",
  "type": "registry:lib",
  "description": "mergeStyle, the object equivalent of cn().",
  "files": [{ "path": "lib/flint/utils.ts", "type": "registry:lib" }]
}
```

A primitive that other primitives need follows the same rule. `text` depends on `theme`, `utils` and
`theme-provider`, so `add text` copies all four files.

## Rules the registry follows

These are authoring rules, not checks in `registry:check`:

- No component imports another component's file unless the dependency is declared.
- No component imports from `@/components/...` in the shared library. Library code is leaf code.
- A file in the registry does not import `node:*` unless it is the font helper.

`test/registry.test.ts` checks that components use tokens, `Text` and `pressable`; the registry
checker verifies structure, paths, dependencies and cycles.
