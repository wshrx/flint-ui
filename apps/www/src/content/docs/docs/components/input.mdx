## Usage

```tsx
import { useState } from "react"
import { Input } from "@/components/ui/input"
import { Icon } from "@/lib/flint"

const [name, setName] = useState("")

<Input
  value={name}
  onChange={(event) => setName(event.value ?? "")}
  aria-label="Display name"
/>

<Input
  placeholder="Search"
  leading={<Icon name="search" size={14} />}
  invalid={name.length > 40}
  aria-label="Search"
/>
```

## Why the border is on a wrapper

GPUI draws its own text box inside the native `<input>`. Padding, border and focus ring belong to
the wrapper so they line up with `Select`, `Textarea` and every other control; the editor inside is
transparent and fills the remaining space. That also makes `leading` and `trailing` possible
without absolute positioning.

## Keyboard and accessibility

Focus lives on the native editor; the wrapper tracks it through `onFocus` and `onBlur` and switches
the border to `ring` with a 2px outline. The caret, selection and key handling belong to GPUI's
editor, and `onChange` reports `event.value` rather than a DOM event. GPUI has no `for=`, so give
the field an `aria-label`; a visible `Label` above it is positional only.

## Notes

- The value comes from `event.value`, not `event.target.value`. There is no DOM.
- `invalid` changes the border and the focus ring. It does not print an error. Pair it with a
  muted `<Text tone="destructive">` under the field, where the message can say what to fix.
- `type="password"` is not supported: GPUIX's editor has no masking yet.
