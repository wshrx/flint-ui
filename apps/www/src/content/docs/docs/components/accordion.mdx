## Usage

```tsx
import { Accordion, AccordionItem } from "@/components/ui/accordion"
import { Text } from "@/lib/flint"

<Accordion defaultValue="billing">
  <AccordionItem value="profile" title="Profile">
    <Text size="sm" tone="muted">Name, photo and the address people see.</Text>
  </AccordionItem>
  <AccordionItem value="billing" title="Billing">
    <Text size="sm" tone="muted">Plan, invoices and the card on file.</Text>
  </AccordionItem>
  <AccordionItem value="danger" title="Delete workspace" disabled>
    <Text size="sm" tone="muted">Unavailable while the workspace has members.</Text>
  </AccordionItem>
</Accordion>
```

Controlled:

```tsx
import { useState } from "react"

const [open, setOpen] = useState<string | null>("profile")

<Accordion value={open} onValueChange={setOpen}>…</Accordion>
```

## Keyboard and accessibility

The trigger spreads `buttonProps` from `@gpuix/react`, so it gets `role="button"`, sits in the tab
order, fires on Enter at key down and on Space at key up, and sets `aria-expanded`.

There is no `aria-controls`, and the panel has no `id` and no `role="region"`. A closed panel is
unmounted, so its content is not in the accessibility tree. A disabled trigger leaves the tab order.

## When not to use it

Use headings and always-visible sections when the reader needs to compare two sections; one open at
a time hides the other. To switch between views at the same level, use `Tabs`.

An accordion holds prose. Do not put a form the user fills in across several panels.

## Notes

A closed panel is unmounted, not hidden: a tall panel costs nothing until it opens, and its state
is discarded when it closes. Keep anything that must survive in the parent.

Clicking the open item closes it, so `value` is `string | null`. There is one mode: single,
collapsible. Multiple-open accordions usually mean the content wanted to be a page, not a
disclosure.
