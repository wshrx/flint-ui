## Usage

Mount the provider once, next to the theme:

```tsx
import { ContextMenuProvider } from "@/components/ui/context-menu"
import { ThemeProvider, flintDark } from "@/lib/flint"

<ThemeProvider theme={flintDark}>
  <ContextMenuProvider>{/* your app */}</ContextMenuProvider>
</ThemeProvider>
```

Then wrap the area that accepts a right click:

```tsx
import { ContextMenu } from "@/components/ui/context-menu"
import { Card } from "@/components/ui/card"

<ContextMenu
  items={[
    { label: "Rename", onSelect: rename },
    { label: "Duplicate", onSelect: duplicate },
    { label: "Delete", onSelect: remove, danger: true },
  ]}
>
  <Card>{/* row content */}</Card>
</ContextMenu>
```

## Keyboard and accessibility

The trigger listens to `onAuxClick` and opens only when `isRightClick` is set. The menu is a
window-level layer: clicking anywhere outside closes it, and Escape closes the top layer through
`DismissableLayer`. The panel is `role="menu"` and items are `role="menuitem"`; the pressable helper
puts enabled items in the tab order, fires Enter on key down and Space on key up, and leaves
disabled items out.

The menu is positioned at the cursor and clamped to the window edges. There are no submenus and no
separators: a right-click menu that needs a hierarchy is a dialog.

## Notes

The provider is not optional. The layer has to live above the scroll container, otherwise a menu
opened near the bottom of a list is clipped by it. Mount `ContextMenuProvider` once at the root.

Coordinates come from the event, in window pixels, so the menu opens where the pointer is regardless
of scroll offset. The panel is 220 px wide and 30 px per item.

## When not to use it

Use a visible toolbar or menu button when the action must be discoverable.
