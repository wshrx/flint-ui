`flint-ui` copies files. It does not install a runtime, run a build step, or modify your source
beyond the files you ask for.

## Commands

| Command | What it does |
| --- | --- |
| `flint-ui init` | writes `flint.json` and copies the shared library |
| `flint-ui add <name...>` | copies components and their dependencies |
| `flint-ui list` | prints the registry, components first |
| `flint-ui diff <name...>` | compares the files in your project with the registry |
| `flint-ui --version` | prints the release the binary was built from |
| `flint-ui help` | usage |

## Flags

| Flag | Applies to | Meaning |
| --- | --- | --- |
| `--root <dir>` | `init`, `add`, `diff` | where files are read and written; default `src` |
| `--registry <path\|url>` | all | local folder or base URL of a registry |
| `--overwrite` | `init`, `add` | replace files that already exist |
| `--dry-run` | `init`, `add` | print what would be written and write nothing |

`FLINT_REGISTRY` is read when `--registry` is absent. `flint.json` is the last fallback before
the public registry.

```bash
flint-ui add button dialog --root app
flint-ui add tabs --registry ./registry --overwrite

# see the plan first
flint-ui add dialog --dry-run

# compare with the registry
flint-ui diff dialog
```

## What add writes

`add dialog` copies seven files. The dialog declares five dependencies, and `icon` pulls in the icon
set, so the tree is:

```text
lib/flint/theme.ts
lib/flint/utils.ts
lib/flint/theme-provider.tsx
lib/flint/icons/index.ts
lib/flint/icon.tsx
lib/flint/text.tsx
components/ui/dialog.tsx
```

Files are copied in that order, each dependency before the item that names it. Dependencies come
from `registryDependencies` in `registry.json`. There is no package manager involved and nothing is
resolved at runtime.

A file that already exists is skipped, not replaced. On a fresh project the command prints:

```text
  add lib/flint/theme.ts
  add lib/flint/utils.ts
  add lib/flint/theme-provider.tsx
  add lib/flint/icons/index.ts
  add lib/flint/icon.tsx
  add lib/flint/text.tsx
  add components/ui/dialog.tsx

7 file(s) added, 0 skipped
```

After `flint-ui init`, the six shared files are already present. The same command then prints
`1 file(s) added, 6 skipped` and copies only `components/ui/dialog.tsx`. Pass `--overwrite` to
replace existing files instead.

## Validation

Before copying anything, the CLI validates `registry.json`: it must parse, `items` must be a
non-empty array, every item needs a name, a type and at least one file path, names must be unique,
and every `registryDependencies` entry must exist. A bad registry fails with one line and a
non-zero exit, before half a component lands in your project.

## Diff

`diff` compares the files under `<root>` with the resolved registry: `--registry`, then
`FLINT_REGISTRY`, then `registry` in `flint.json`. When no registry is set, `init` writes one pinned
to the CLI version, so the default comparison stays on the release you initialised with.

| Exit code | Meaning |
| --- | --- |
| `0` | every file matches the registry |
| `1` | at least one file changed, is missing, or the registry could not be read |

```text
  changed  components/ui/dialog.tsx (128 → 131 lines)

1 changed, 0 missing, 6 unchanged
```

An unknown component or a failed download also exits `1`.

## Adding your own registry

A registry is a folder with `registry.json` and the files it names. Point the CLI at it locally
while you build components for your team:

```bash
flint-ui add pricing-table --registry ../our-registry
```

See [Registry](../registry/) for the file format.
